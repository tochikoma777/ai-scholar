## 0. TLDR（红线速查）

### 0.1 工作方式（先看这个）

1. **你是执行者**，项目负责人是决策者。**每个里程碑结束后停下**，输出验收报告，不要开始下一阶段。
2. **一次只做一件事**。给你的待确认项超过 1 个 = 节奏失控的信号。
3. **不确定的列出来问**，不要自作主张。
4. **全程中文回复**（技术术语、代码、路径除外）。

### 0.3b ★ 双仓库五条防护（v1.2 新增，vault 迁出后必守）

> vault 是**独立 private 仓库**；代码仓库是 public。二者之间的裂缝必须堵住。

| # | 风险 | 对策 |
|---|---|---|
| 1 | 绝对路径泄露用户名到 config | config 只准 `~/` 开头；单测断言不含 `/home/` `/Users/` |
| 2 | ★ **CI 日志泄露路径**（Actions 日志**默认公开**） | CI 禁止默认路径 export（用 tmp 目录）；日志脱敏 |
| 3 | `example_vault/` 与真 vault 混淆 | 单测断言默认路径 ≠ example_vault；**写入前校验目标不在代码仓库内**，在则报错拒绝 |
| 4 | ★ **vault 无备份 → 笔记永久丢失** | vault `git init` + private remote；`doctor` 检查无 remote 时 **warning** |
| 5 | git 与云同步打架 | vault 用 git 就**不要**叠加 Obsidian Sync / iCloud |

★ **为什么第 4 条最严重**：`first_seen`/`signals` 有 JSONL 落 public、db 可重采，
**只有用户笔记丢不得** —— 它是全项目唯一不可再生、不可重采、无备份的数据。

★ **`export --check`**：真 vault 不在版本控制里 ⇒ `git diff` 检查不到它 ⇒
幂等失去自动验证。该模式输出"将要变更的文件列表"（正常应为空，退出码 0/1），
让幂等**可被 CI 断言**。

### 0.4 三个最容易做错的点

| 点 | 常见错误做法 | 正确做法 |
|---|---|---|
| **新论文的引用数据** | 入库时查一次，查不到就放弃 | **必须实现补齐队列**（新论文的 citations 必然为空，要等几周） |
| **外部源的超时** | 用全局 20s 超时，一天失败就整源报错 | ★ **按源配置**（arXiv **600 条/页**需 60s，`collect.arxiv_read_timeout_s`）+ **逐日隔离**（部分失败记 `_partial`，不拖垮整源） |
| **关联回写** | 只写单向，B 页面看不到 A | ★ **不是**双向存储：出边落 `paper_links`，**入边靠 `idx_links_dst` 反向查询**；对称边（语义相似）只存一条（`src < dst`），渲染时双向展开（红线 14 / 24） |
| **推演** | 所有推演都进记分板 | **不可证伪的洞察必须标注为「观点」，不计入统计** |

## 1. 工作方式

### 1.1 阶段内流程

```
读 SSOT（指定章节）→ 实现 → 自测门禁 → 输出验收报告 → 停下等确认
```

**不要跳步**。尤其不要"顺手"做下一阶段的事——这是 aipulse 中反复出现的问题。

### 1.2 读文档的方式

- **不要全量读设计方案**（★ v1.1：已约 1100 行，原为 580）。读项目负责人**点名的章节**。
- 每个里程碑开场，项目负责人会给出「本次重点章节」。
- 常用点名：§3.2 去重与 hash · §3.3 时间语义 · §3.7 数据落点 · §5 关联 · §5.5 深度分析 · §5.6 vault 边界 · §6 Obsidian 输出 · §12 实测数据
- 通用工程规范见 `经验固化-通用开发原则.md`（若项目引入）。

### 1.3 提交与文档

| 顺序 | 步骤 |
|---|---|
| 1 | 代码完成 → 自测全绿 |
| 2 | **提交 + 打 tag**（如 `l0b`） |
| 3 | 项目负责人刷新 SSOT 与 `文档维护日志.md` |
| 4 | 你**不要**改 SSOT 与维护日志 |

**★ 为什么要这个顺序**：维护日志要记录「文档版本 ↔ tag」。代码没提交就写不出 tag 列——
**写不出来就说明顺序错了**。这条纪律的价值在于它**可执行**。

★ **禁止 force 更新 tag**（L0-A 因补 commit 重打过一次；新仓库可接受，之后不再允许）。

## 2. 红线详解

### 2.1 数据真实性类

| 红线 | 说明 |
|---|---|
| **禁止伪造 fixtures** | 需要真实 API 响应时，真实抓取；抓不到就 `pytest.skip(reason=...)` 并写明原因 |
| **探测结果必须真实** | 数据源探测记录**真实响应片段与字段**，字段表只能从真实响应摘取 |
| ★ **不用"本地测不到"推断"源不可用"**（v1.1 强化） | `availability` 描述的是**"源本身是否公开可用"**，不是"从我的 WSL 能不能访问"。本地失败 → 加 `*_base_url` 配置项让用户填镜像，不可达时 warning + 跳过，**不把网络问题编码成源属性** |

### 2.2 LLM 相关类

| 红线 | 说明 |
|---|---|
| **off 档零调用** | `build_client` 返回 NullLLM；respx 断言 0 请求 |
| **未配置 api_key 自动降级 off，不报错** | 违反即为崩溃级 bug |
| **三级降级阶梯** | `json_schema → json_object → plain`；**plain 是万能兜底** |
| **降级状态按 (model, format) 记忆** | 不能全局布尔（不同模型支持情况不同，全局会连坐） |
| **输出紧凑** | 不回显输入，只返回必要字段 |
| **超时分层** | fast/strong 分别设置；推理型模型输出更长 |
| **结果持久化** | 同一输入不重复生成（content_hash + TTL + 失效条件） |
| **可证伪性由代码判定** | LLM 不得输出"无法验证"这类自我豁免 |
| ★ **prompt 是代码资产**（v1.1 新增） | prompt 放 `src/ai_scholar/prompts/*.j2`，**不放 docs**；改 prompt 必须触发对应单测 |

### 2.3 输出与文件类

| 红线 | 说明 |
|---|---|
| **★ 标记块** | 生成内容必须在 `<!-- BEGIN/END GENERATED -->` 之间；用户区永不覆盖 |
| **★ frontmatter 合并** | 生成时读现有 frontmatter，保留用户字段（如 `status`） |
| **★ 文件名清洗** | 非法字符替换、去重 `-`、长度截断、日期前缀、hash 兜底 |
| **原子写入** | 写临时文件 + rename（避免同步工具读到半截文件） |
| **导出幂等** | 无变化时重复导出**不产生 diff**；单测断言"连续两次导出无 diff" |
| **空态显式** | 无关联/无点评时显示 `—` 或"暂无"，不静默省略 |
| ★ **文件内只留内容级时间戳**（v1.1） | `generated_at` → **`content_rev_at`**，仅 why/note 内容变化才更新；**标记块注释去掉内嵌时间戳**；导出时间只进 `90-元数据/生成报告.md` |
| ★ **`citations` 不要每次导出都更新**（v1.1） | 它是观测值，每次更新会产生海量 diff；**只在笔记被重新生成时（深度分析/定级触发）才更新** |
| ★ **关联文献区用双轨**（v1.1） | 有 vault 笔记 → `[[双链]]`；无笔记 → **文本标题 + arXiv/HF 外链**，**不建空笔记** |

### 2.4 工程类

| 红线 | 说明 |
|---|---|
| **单源失败不影响退出码** | 可选源失败 → 退出码 0 + 记录 degraded |
| **不引入 openai SDK** | httpx 直连（SDK 会阻碍 mock） |
| **统一走 HttpClient** | 限速/重试/代理/UA 复用；LLM 层关 HTTP 缓存 |
| **mypy strict** | 不用 `# type: ignore` 掩盖，错误码不匹配时用 `cast` |
| **不用 `ubuntu-latest`** | 固定 `ubuntu-24.04` |
| ★ **S2 全程 batch**（v1.1 新增） | `POST /graph/v1/paper/batch`，500 ids/次，`fields` 走 URL query，Header `x-api-key`；**禁止逐篇 GET** |

## 3. 环境分级（★ v1.1 修订）

| 分级 | 含义 | 处理 |
|---|---|---|
| `always` | 源本身公开可用 | 正常实现；本地不可达时 **warning + 跳过**，不计失败 |
| `actions_only` | 只在 Actions 采集 | 本地跳过且**不计失败**；★ 当前**没有任何源使用**（v1.1 起全部改回 `always`） |
| ~~`optional_enrich`~~ | ~~可选增强源，可能不稳定~~ | ★ **代码中已不存在该档位**（`Availability = Literal["always", "actions_only"]`）；原拟用于 OpenReview，而 OpenReview 未实现 |

**★ 判据**：`availability` 描述**"源是否公开可用"**，不是"我这儿能不能访问"。
本地失败时先确认是网络问题还是源本身不可用（用 Actions 触发一次验证）。

**当前分级**：

| 源 | 分级 | 说明 |
|---|---|---|
| arXiv API | `always` | 限速约 1 req / 3s；★ 端点用 **https**（http 会 301） |
| HF Daily Papers | `always` | ★ v1.1：由 `actions_only` 改回 `always` + 新增 `hf_base_url` 配置项（可填镜像） |
| Semantic Scholar | `always` | 只走 `paper/batch` |

> ★ v1.1 起不再使用 `actions_only` 档（它会把一次本地 ConnectTimeout

### 4.5c ★ vault 笔记选集策略（v1.5 定案，堵一个会爆的漏洞）

**问题**：默认 `export --limit 20` 取"最新 20 篇"，而库每天新增 515 篇
⇒ **每天 export = 造 20 篇笔记 = 7,300 篇/年**，是 §5.6 目标（300–500/年）的 **15 倍**。
（L1-A 实跑已产生 40 篇笔记，是早期信号。）

| 项 | 规则 |
|---|---|
| 字段 | `papers.selected BOOLEAN`（默认 0） |
| `export` | ★ **默认只导出 `selected=1`**；`--all` 才按 `--limit` 导出最新（demo/调试用） |
| 置位途径 | 深度分析完成（L3）· 显式收藏 `ai-scholar mark`（L1-B）· 从报告点读（L2） |
| 空态 | 无 selected 时**明确提示**"用 `mark` 或 `--all`"，**不要静默导出 0 篇** |

⚠️ **必须在 L2 自动化之前完成** —— 否则每天自动跑 = 每天污染 vault。

### 4.5b ★ 生成报告不进 vault 的 git（v1.3 定案）

加入 vault 的 `.gitignore`。理由（详见设计方案 §6.1.1）：
① **让 `git status` 成为干净信号** —— 报告每次必变会让仓库永远脏，
导致真正该备份的笔记变化被忽略 ② db `runs` 表已有完整运行历史，不丢数据。

⚠️ **已知局限**：`--check` 只校验本次选集（默认 20 篇），范围外旧笔记不在检查内；
全量校验 `--check --all` 在 **L1-B** 补。

## 8. 与安全相关的硬约束

> 这些是 aipulse 中**真实造成过损失**的，本项目必须一开始就遵守。

| 约束 | 说明 |
|---|---|
| **删除前确认** | 每次删除都要列清单 + 停下确认；"觉得不用确认"时**仍然要确认** |
