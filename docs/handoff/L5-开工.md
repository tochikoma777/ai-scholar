## 3. L5 范围与硬约束

**L5a（先做）**：静态 HTML 单文件导出（Exporter 第二实现，零新增依赖）。

- 输入只读：`data/reports/*.json` + `data/predictions/scoreboard.jsonl` + db 论文元数据；
- **绝不读取 vault**（私有笔记不进 public 产物）；
- 输出自包含：CSS 内联、无外链 CDN、双击可开；
- 展示分项分（热度 / 跨源 / 主题），**不得加权成单一总分**。

**L5b（L5a 验收后）**：交互式 Web 看板，优先**单文件 + 原生 JS + 内嵌 JSON**
（筛选 / 排序 / 搜索），仍零后端；只有明确出现「多用户 / 实时数据 / 权限」需求时，
才评估 server / SPA（届时单独成本与部署决策）。

**为什么不在 L5a 直接合入完整 Web 看板**：

- 完整看板会引入前端构建 / 服务进程 / 托管，违背「零新增依赖、单文件可开」；
- CI 目前是纯 Python 单矩阵，加 JS / E2E 测试会扩大维护面；
- 看板一旦可分享，私有数据边界与权限问题必须重新设计（当前明确不碰笔记）；
- 先交付 L5a 能立刻验证「HTML 是否好用」，再决定 L5b 的最小交互形态，避免一次做两个产品。

硬约束：

- 任何导出形态必须仍是**自包含、可直接喂给别的 AI 工具**的合成文档；
- 不得改变已有数据落点（vault 仍由本地 `export` 写 private 仓库）；
- 不得把个人笔记、私有路径、API key 写进 HTML。
