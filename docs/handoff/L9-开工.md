## 2. 每天在自动跑什么（先看懂再动手）

`daily.yml`（UTC 16:30 / 北京 00:30）：

```
collect → collect --classics → enrich → signals → relate → enhance → grade
→ analyze → analyze --check → predict → stats --verify → report
→ Cost guard（::warning）→ Build site → Upload Pages → Commit → deploy-pages
```

- LLM 环节：`enhance`(fast, 20) · `grade`(fast, **8**) · `analyze`(strong, 日 1 篇 / 周 5 篇上限；L9-E 削峰，见 `docs/任务卡/L9-E-配额削峰.md`)。
- 预算闸门：`budget.daily_limit_cny=2.0`，调用前拦截、只降级不报错。
- ★ 另有 `recap.yml`（周一 / 每月 1 号 UTC 16:35）：`report --weekly|--monthly --previous`，
  与 daily **共用** `concurrency: ai-scholar-daily`，只提交 `data/reports/{weekly,monthly}`。
- ★ 报告目录已分层：`data/reports/{daily,weekly,monthly}/`（读取器兼容旧平铺，`report_paths.py` 统一）。
- 成本可见性**四处**：报告 md 顶部 ⚠️ / 报告 json `cost_anomalies` / 站点「成本」板块 / Actions `::warning`（另有 `ai-scholar cost` 随时查账）。

## 4. 已知遗留（不是新 bug，别重复排查）

| 现象 | 原因 | 处理 |
|---|---|---|
| 本地 `huggingface.co` ConnectTimeout | 本机网络环境（Actions 正常） | 属预期；不要为此改代码 |
| S2 `HTTP 429`（enrich） | 无 API key 的限流 | 队列重试；要根治需付费 key |
| 报告里出现 `arxiv: ReadTimeout` | `Report` 汇总的是**当天所有 run**，可能是早前 run 留下的 | 先看本轮 `Collect` 表是否为 OK；只在 `arxiv_partial` 里出现才算本轮部分失败 |
| classics 偶发 `429` | arXiv 限速 | 20s/40s 退避已内置；连续失败才需关注 |
| `data/analyses/` 有、vault 无 | 该论文不在**本地** db（Actions 与本地两份 db） | 本地跑一次 `ai-scholar collect` 再 `export` |
| fast 档 ~1/30 解析失败 | 模型偶发不按 schema | 不写指纹、下次重试；持续升高再查 prompt |
