## 3. 范围与 DoD

**L6-1 HF daily HTTP 400（✅ 已修）**

- **根因（2026-10-25 实测，非推断）**：HF 官方 API 的 `date` **上限是"昨天"**。
  当天榜单尚未发布 ⇒ 请求 `?date=<今天>` 返回 400：
  `{"error":"✖ \"date\" must be less than or equal to \"<今天>T00:00:00.000Z\""}`。
  镜像站同行为（`hf-mirror.com` 实测一致），**不是网络/镜像问题**。
- **为什么以前没暴露**：daily 跑在 UTC 16:30（北京 00:30），`today_local()` = 当天，
  HF 被请求当天 ⇒ 每次必 400。但 10-24 那次成功的 run 抓到 31 篇 HF 论文，
  是因为更早的手动 dispatch 跑在 10-23（那时"昨天"有数据）。
- **修法**：
  - `collectors/hf.py::hf_collect_days()` 采集窗口**从昨天开始**（不含今天），
    与 arXiv 的滞后语义一致（HF 本来就滞后 2~4 天）；
  - `fetch_hf_day` 失败时带**截断响应体**（≤300 字符），状态码不再孤证。
- **未做**：不自动切镜像；`availability` 分级不改（官方仍是 `always`）。
- **DoD**：daily 下一次跑 `hf_daily` 不再 400；degraded 为空。
  ✅ **已验证（2026-10-25 09:26Z，workflow_dispatch run 40180596401）**：
  collect 的 HF 状态为 `OK`（fetched 249 / new 1），7 个日期请求全部 HTTP 200。
  ⚠️ 报告里残留的 `HF HTTP 400` 来自 `runs` 表中**上一次（10-24，旧代码）**的历史行，
  不是本次失败 —— `build_daily_report` 按本地日窗口聚合，跨天的历史 run 会被带进来。
