## 3. 范围与 DoD

**L6-1 HF daily HTTP 400（最高优先）**

- 证据：daily run #4（2026-10-24T18:55Z）与 #3 日志均报 `HF HTTP 400`；
  bot 版报告 `degraded={"hf_daily": "RuntimeError: HF HTTP 400"}`。
- 现状：`collectors/hf.py` 只报状态码，不带响应体；无法判断是
  API 变更 / 日期无数据 / IP 被限。
- **DoD**：`fetch_hf_day` 失败时带**截断的响应体**（≤300 字符）与 URL/日期；
  用 `workflow_dispatch` 跑一次 probe 取证；给出结论（可修 / 需配镜像 / 外部问题）。
- ★ 不自动切换镜像；如需镜像，只改配置并在文档记录。

**L6-2 成本可见性（G2 闭环）**

- 现状：`DailyReport.cost_cny` 字段存在，`build_daily_report()` 从不填充；
  `daily.md.j2` / `site` 因此永远不显示成本。
- **DoD**：按**本地日窗口**汇总 `llm_usage.cost_cny` 写入 `cost_cny`；
  `report` 的 md 出现「当日实际 ¥X」；`site` 概览显示当日成本；
  `off` 档显示 ¥0（不是 `—`）；加测试覆盖「有花费 / 无花费」两条。

**L6-3 数据来源防覆盖（流程，非代码）**

- 现状：L4 本地提交覆盖了 bot 的 10-25 报告，导致 `runs` / `degraded` 证据消失。
- **DoD**：CODEBUDDY / 经验固化 G5 已写明；若发现可机械化的检查（如报告
  `runs=[]` 且 `data/signals` 当日有新增 ⇒ 报警），再单独提，不阻塞。

**明确不做**

- 不改 L5b 的筛选/排序范围；不做 daily.yml 发布；不引入前端构建链 / 服务端。
