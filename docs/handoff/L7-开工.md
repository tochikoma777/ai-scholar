## 3. 已定决策（v1.11，勿推翻，除非任务卡明说）

- **排序依据 = 方案 D**：热度 / 经典交替 + 已读去重；热度侧=`hf_score` 非空当日新增，
  经典侧=成熟(≥180天)或被引(≥3)或种子清单/引用榜；交替取两侧最高分。
- **Tier 1 不是深度分析门槛**：通道 B 是并行补读来源（§5.5 原有 ⚠️ 修正，勿再误判）。
- **经典获取 = 种子清单 `config/classics.yaml`（主）+ 库内引用榜（辅）**；
  种子清单用 arXiv `id_list` 批量直采；2026-10-25 已实测 33 个候选 ID 全部命中。
- **深度分析产物 = public 真源** `data/analyses/{id}.md`（Option B），
  本地 `git pull` 后 `export` 物化进 vault，不重复花钱。
- **自动跑**：`analyze` 进 daily.yml（需 LLM secret），报告自动出现「深度分析」清单。

## 4. 范围与 DoD（全部有设计出处，见 `设计方案.md` §8.8）

| # | 接线项 | DoD（可断言） |
|---|---|---|
| 1 | `analyze` 接入 daily.yml | 工作流含 analyze 步骤；`off` 档时 0 调用退出 0 |

| 6 | 报告点读置位 | 有从报告/站点「标记想读」的入口，落 `selected=1` |
| 7 | `links.json` 填真实关联 | 含出边/入边/相似/耦合，非 `[]` |
| 8 | frontmatter `score` 落分项分 | 笔记 frontmatter `score` 为热度/跨源/主题，非 null |

**硬约束不变**：不读 vault 渲染 public、分项分不合成总分、幂等、`off` 档零调用、
