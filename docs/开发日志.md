# 开发日志

> Agent 维护。只记"为什么这么做"与踩到的坑，不记流水账。

## L0-A（仓库创建 + 骨架 + 配置层 + 数据源探测）

### 决策与依据

1. **`config/default.yaml` 里的环境开关一律 `${ENV}` 占位符**
   `load_settings()` 用 `Settings(**yaml)` 构造，init kwargs 优先级**高于**环境变量。
   写成字面量会把 `AI_SCHOLAR_MODE` 之类的环境变量**静默压掉**（aipulse 的真实坑）。
   单测 `test_literal_yaml_defeats_env` 把这个反例固化成了断言。

2. **`effective_mode()` 把 `base_url` 和 `api_key` 一起判空**
   只配 key 不配 base_url 的环境（典型是 CI 只注入 key 的 secret）会一路走到客户端构造处崩溃。
   缺任一 ⇒ 自动降级 `off`，退出码 0。

3. **watchlist 同名组"整组覆盖"而非逐字段合并**
   半合并会产生"权重来自 A、关键词来自 B"的组，命中分数无法解释。
   local 没写的组完整回落 default。

4. **CLI 的 `list` 命令函数改名 `list_papers`**
   `def list(...)` 会遮蔽内建 `list` 类型，mypy strict 直接报
   `Function "ai_scholar.cli.list" is not valid as a type`。命令名仍由 `@app.command("list")` 指定。

5. **`SourceSettings.source_extra()` 必须走 `model_extra`，不能用 `getattr`**
   `getattr(self, "categories")` 会先命中同名的**方法** `categories()`，返回一个 method 对象
   （aipulse 的 `fallback_endpoints` 是同一个坑）。

6. **arXiv 端点用 https**
   `http://export.arxiv.org` 会 301 到 https，在本环境还额外拖慢连接。

7. **测试必须隔离开发者本地的 `.env`**
   跑过 `ai-scholar init` 后仓库根就有 `.env`，而 `load_settings()` 会 `load_dotenv()`。
   结果"缺 base_url 应降级 off"这条断言**本地失败、CI 通过**。
   且 python-dotenv 是按**调用者文件位置**向上找 `.env`，不是按 cwd —— 只 `chdir` 不够，
   必须在 conftest 里把 `ai_scholar.config.load_dotenv` 打桩掉。

### 环境实测

| 源 | 本地 WSL | GitHub Actions | 结论 |
|---|---|---|---|
| `export.arxiv.org` | ✅ HTTP 200 | ✅ HTTP 200 | `always` |
| `huggingface.co` | ❌ ConnectTimeout | ✅ HTTP 200 · 50 条（手动触发 ci.yml 的 probe job） | `always`（见下方分级决策） |
| `hf-mirror.com` | ✅ HTTP 200 | 未测 | 仅作探测对照 |

★ HF 官方端点在 Actions 可达是**实测**结论（不是推测）：`gh workflow run ci.yml` 触发 probe job，
日志显示 `→ HF/official https://huggingface.co/api/daily_papers?date=2026-10-20` → `HTTP 200 · 300952 B`。

★ **availability 语义（项目负责人拍板）**：它描述"源本身是否公开可用"，**不是**"从某台机器能不能访问"。
本地 WSL 连不上官方 HF 是网络环境问题，不改变分级 —— 所以 `sources.hf_daily.availability = always`，
配 `hf_base_url`（镜像，`${ENV}` 占位符）即可解；不可达只 warning + 跳过该源，**不计失败、不影响退出码**。

★ 不替用户决定镜像站：`hf_base_url` 默认官方，用户自行覆盖；探测脚本 `--hf-mirror` 也须显式指定。

### 实测规模

| 探测日 | N_arxiv | N_hf | N_enter | 去重后保留比例 |
|---|---|---|---|---|
| 2026-10-19（本地） | 518 | 50 | 236 | 0.415 |
| 2026-10-20（本地，10-22 探测） | 465 | 50 | 230 | 0.447 |

★ 日间波动明显（465 ~ 518），**做体积估算要用区间而不是单点**。最新完整明细见
`docs/数据源手册.md`。

### 三个 N 的口径（★ 收尾时澄清，避免算术矛盾）

链条：`N_arxiv（单日，去版本号去重） → 并集 U（+N_hf，交集 0） → N_enter（领域过滤后）`。

- **N_arxiv**：arXiv **单日**（`submittedDate` 精确框定某天，`cat:cs.AI OR cs.CL OR cs.LG`），
  按 arXiv id 去版本号去重后的条数。**不是窗口**。max_results 分页抓全（单页 200）。
- **N_hf**：HF Daily Papers 当日上榜条数。
- **N_enter**：并集 U 经领域过滤（watchlist 命中 `threshold=0.9`）后**进入系统**的条数。
- 之前报告的"重叠率 0.459"**不是重叠率**，是**去重后保留比例** `N_enter / (N_arxiv + N_hf)`（定义写错过）。
- **两源真实交集 = 0**：HF 上榜论文的 arXiv id 都不在"当天提交的 arXiv 集合"里（滞后 2~4 天），
  但 50/50 都能在 arXiv **全库**回查到 —— "能查到"≠"当天集合里"。

★ **索引补全**：`submittedDate` 框定某天的 total **会随时间补全增长** ——
2026-10-20 这天，10-21 探测是 362，10-22 探测是 465。用 D-2 前推仍可能不完整，
**拿 N_arxiv 做估算时必须注明"探测日"，并接受它是下界**。

★ 一个反直觉的实测结果：**HF 上榜论文相对其 arXiv 提交日滞后中位 2~4 天（最大可达 112 天）**，
且 50/50 都能在 arXiv 查到。所以"同日交集"天然为 0，两源重叠必须按 **arXiv id** 判定；
"今天新发现了什么"只能用 **discovery**（`first_seen`）过滤，不能用 `published`。

## L0-B（DB schema + 采集器 + 三级去重 + first_seen）

### 决策与依据

1. **`content_hash` 与"观测值"分离**（红线 14）
   hash 只吃 `title + abstract + authors + venue`；`hf_score` / `citation_count` 照存
   `papers`，时序快照留给 `signals` 按天一行。
   ★ 单测除了断言"改观测值不改 hash"，还加了**反向断言**（改标题/摘要/作者 hash 必变）——
   否则"不变"测试可能只是恒等函数的假绿。

2. **作者归一化必须处理逗号格式**
   初版只按"名在前、姓在后"取 `tokens[-1]` 作姓，结果 `DOE, John` 被算成 `john d`、
   `John Doe` 算成 `doe j` ⇒ 同一作者两个 hash（跨源假重复）。
   已改为：含逗号时逗号前是姓。

3. **watchlist 在采集链路里被**彻底**隔离**
   不是"调用但不生效"，而是 `pipeline/collect.py` **根本不 import** watchlist，
   并用源码级单测（`test_pipeline_never_imports_watchlist`）钉死。
   理由（设计方案 §4.2.1）：领域过滤已在 arXiv 查询的 `cat:` 里做过，
   再滤第二遍会让 `N_enter` 随个人配置漂移、且关联图只剩我关心的方向。

4. **db 是缓存，JSONL 是真源**
   `papers.first_seen_at` 只是 `data/first_seen.jsonl` 的缓存副本；
   JSONL append-only（已有 id 跳过），所以 db 可随意重建而首见日不丢。

5. **`dry-run` 不碰磁盘**
   db 文件不存在时用内存库做统计，不凭空造出 `ai_scholar.db` 文件。

### 踩到的坑

1. **alembic autogenerate 生成的迁移缺 `import sqlmodel`**（用到了
   `sqlmodel.sql.sqltypes.AutoString()`）⇒ `upgrade` 直接 `NameError`。
   修法：把迁移里的 `AutoString()` 换成 `sa.String()`。
2. **`script.py.mako` 不在仓库里** ⇒ `alembic revision` 报 FileNotFoundError。
   模板已补进 `alembic/`。
3. **`arxiv_max_results` 默认 200 会截断当天**（单日实测 465）⇒ 提到 600。
4. **静态断言"禁用 datetime.now()"会命中 docstring**：
   `store/models.py` 的文档里写了 `datetime.now()` 字样就被扫出来。改措辞即可。
5. **`collect` 从占位变实现后，旧单测失败** —— 占位命令测试要同步收窄到
   `export` / `list`（`collect` 已不再是占位）。

### 实测（2026-10-23，本地）

| 项 | 值 |
|---|---|
| arXiv `--days 2`（10-21 + 10-22） | fetched 320 / new 320 |
| 第二次同样命令 | new 0 / deduped 320（papers 行数不变） |
| `first_seen.jsonl` | 第一次 +320 行，第二次 +0 行 |
| HF（镜像 `hf_base_url`） | fetched 42 / new 31 / deduped 11（11 条命中 arXiv 已入库条目，只补 `hf_score`） |

（10-22 当天还没补完）。这再次印证 §12 的"N 是下界"。

## L0-C（Obsidian 导出器 + list）

### 决策与依据

1. **导出幂等 = 文件内不留任何"会变的量"**
   - 标记块注释去掉时间戳（原稿 `· 2026-10-17T08:00:00+08:00` 每次导出都变）；
   - `generated_at` → `content_rev_at`（日期级，且只有生成区内容变了才更新）；
   - **`90-元数据/生成报告.md` 的导出时间也降级为日期级** —— 否则"连续两次导出无 diff"
     这条头号验收项永远不可能通过（同一天两次导出必须完全一致）。
     秒级时间改由 db 的 `runs.started_at` 提供。

2. **`citations` 已有值保持不变**
   它是观测值，每次导出都更新会产生海量 diff。本阶段没有"重新生成"触发源，
   所以读-合并-写回时**保留旧值**。

3. **文件名尾部固定带 8 位短 hash**
   §6.2 说"重名兜底"才加 hash。我选择**总加** —— 因为 arXiv 标题撞车（Re: 同名）
   真实存在，且固定后缀让"同一篇论文的文件名"稳定（换标题也不会丢链）。

4. **`--limit` 默认 20、默认不全量**
   §5.6 明确否掉全量导出（年增 18.8 万篇会让 Obsidian 不可用）。
   本阶段只实现机制（范围参数），三类选择策略在 L3 落地。

5. **`exporter.render()` 自己读目标文件**
   frontmatter 合并必须看到旧文件；把"读"放进 render 而不是调用方，
   避免调用方忘记传旧内容导致 `status` 被覆盖。

### 踩到的坑

1. **SQLModel 字段不能直接 `.desc()`**（mypy strict：`str | None` 没有 `desc` 属性）
   → 用 `sqlalchemy.desc(sqlmodel.col(Paper.published_at))`。
2. **YAML 把 `2026-10-18` 解析成 `datetime.date`** → 读-合并-写回时
   `content_rev_at` 在 `date` 与 `str` 之间抖动，幂等崩掉。
   修法：`parse_frontmatter` 把 date/datetime 统一收敛成 ISO 字符串。
3. **`list` 的 ★ 断言会假绿**：脚注里也有 `★ = watchlist 命中`，
   导致 `assert "★" in output` 恒真。改成断言**表格行**以 ★ 开头。
4. **测试用的 tmp 目录没有 `watchlist.yaml`** → 全部不命中。
   测试必须先安装一份 watchlist 再断言命中数。

### 实测（2026-10-23，本地）

| 项 | 值 |
|---|---|
| `export --limit 20` | 20 篇笔记 + 00-首页 + 生成报告 + links.json（22 个 .md） |
| 连续两次 export | `diff -r` 无差异（幂等） |
| 手改 `status: 已读` + 用户笔记 | 再次 export 后**原样保留** |
| `list` | 显示 ★ 命中标记；`--watchlist-only` 只做展示筛选（库行数不变） |
| `llm_usage` | 0 行（导出零 LLM 调用） |

## L1-0（vault 迁出 + 双仓库防护 + 报告时间戳修正）

### 决策与依据

1. **vault 物理迁出**：`~/projects/ai-scholar/vault/` → `~/projects/ai-scholar-vault/`
   （独立 private 仓库）。迁移前先列 23 个文件清单、确认用户笔记区为空，再用 `mv` 搬（不重建）。
2. **`export.out_dir` 只准 `~/` 开头**：默认 `~/projects/ai-scholar-vault`。
   写死家目录绝对路径会 ① 泄露用户名 ② 别人 clone 后路径不存在。
3. **写入前校验目标不在代码仓库内**（含 `example_vault/`）—— 命中直接抛
   `UnsafeOutputPath`，不降级。这是"防手滑 `git add -A`"的最后一道闸。
4. **`export --check` 的比对范围 = 幂等范围**：文献笔记 + `00-首页.md` + `links.json`；
   `生成报告.md` 是运行日志，按设计允许 diff，**不参与比对**。
   否则秒级时间会让 `--check` 永远非空（与 DoD 直接冲突）。
5. **生成报告恢复秒级**：L0-C 为保幂等把时间降到日期级，是"收窄数据精度换验收"的
   错误取舍；正确做法是收窄幂等验收范围（设计方案 §6.3 v1.4）。

### 踩到的坑

1. **`AI_SCHOLAR_ROOT` 既是"仓库根"又是测试的临时目录**：把 vault 放在 `tmp_path/vault`
   会被"目标不得在仓库内"的校验拒绝。测试必须把 `root` 与 `vault` 分成两个目录。
2. **config 路径泄露测试被自己的注释误伤**：注释里写了反例 `/home/<用户名>/`，
   扫描整段文本会命中。改为**跳过注释行**再断言，同时把注释里的字面量去掉。
3. **`git ls-files | grep vault/` 会命中 `example_vault/`**：DoD 的本意是 `^vault/`；
   `example_vault/` 是**故意入仓**的示例，不能一刀切。

## L1-A（S2 关联：引用入库 + 补齐队列 + 双轨渲染）

### 决策与依据

1. **方向语义先钉死再写代码**：`paper_links(src,dst,'references')` == **src 引用了 dst**；
   入边**不单独存储**（`idx_links_dst` 反向查询即得）。先写三组单测（出边 / 入边 / 互为反向），
   再写实现 —— 方向建模错误能通过所有测试，只是结果反了（执行手册 §0.4）。
2. **只存库内目标的边**：被引目标不在 `papers` ⇒ 不写边，只累加 `refs_count`。
   实测 31,542 条 references 只命中 3 条库内 —— 若按需回采被引论文会引入 ≈1.5 万条/天。
3. **补齐队列复用 `papers` 表**（`enrich_state` / `enrich_attempts` / `enrich_last_at` / `enrich_error`），
   不新建队列表；状态机 `pending → done | stale`，超 `max_attempts` 标 stale 并记原因。
4. **新增 `papers.note_path`**：双轨渲染必须知道"目标有没有 vault 笔记"，
   扫目录每次 O(n) 且文件名含短 hash、匹配不可靠；一个字段胜过一张表，导出时回填。
5. **`batch_size` 超限自动降半**（500 → 250 → 125 …）：S2 单响应 ≤10MB，
   413/400 时降半重试，降到 `MIN_BATCH_SIZE` 仍失败才抛异常。
6. **冷启动期边稀疏是预期**：§5.1b 已定，验收**不因"边少"判失败**。

### 踩到的坑

1. **`Settings()` 不带 `sources`**：测试里必须用 `load_settings()`（读 `config/default.yaml`），
   否则 `settings.source("semantic_scholar")` 是 None。
2. **S2 响应的条数必须与请求 ids 对齐**：未命中的 id 返回 `null`。
   测试里 mock 只给 1 条而请求 3 个 id ⇒ 代码判定"条数不一致"直接跳过写边（表现为"边数为 0"）。
   修法：mock 按请求 ids 逐条返回。
3. **config 里 `api_key: ${AI_SCHOLAR_S2_API_KEY}` 无默认值** ⇒ YAML 解析成 `None`，
   pydantic 直接 ValidationError，所有配置测试一起红。修法：`SourceSettings.api_key`
   加 `mode="before"` 校验器把 None 收敛成空串（与 `LLMSettings` 同一套路）。
4. **无 key 时 S2 限流极严**（实测 429 频发，重试 3~8 次才成功一次）：
   因此实测脚本要带重试；`enrich` 失败只记 degraded，attempts 照常累加。
5. **跨天 `--check` 误报（L0-C 遗留、L1-A 暴露）**：标记块两侧的换行是写入框架，
   不属于生成区内容；`old_generated == new_generated` 因此**永远不成立**，
   跨天后 `content_rev_at` 会被刷新（同日多次导出看不出来）。
   修法：比较前 `strip("\n")`，并加"跨天内容不变 ⇒ 整文件不变"的回归单测。

### 实测（2026-10-23，本地，无 S2 api_key）

| 项 | 值 |
|---|---|
| D2 三数（50 篇样本） | 解析率 **98.0%**（49/50）· `referenceCount>0` **89.8%**（44/49）· 中位数 **40**（0~100） |
| 第一次 enrich（351 篇库） | 199 命中 / 8,060 references / **库内命中 0** |
| 补采默认回看 7 天后 enrich（2,174 篇库） | 1,696 命中 / 31,542 references / **库内命中 3** ⇒ 出边 3 |
| `related` | src 侧显示「引用了」，dst 侧显示「被引用」，同一条边互为反向 |
| `export --check` | 无变更，退出 0（新渲染未破坏幂等；★ 跨天复测同样为 0） |
| `llm_usage` | 0 行 |

## L1-B（signals 采样 + 预筛 + 选集策略）

### 决策与依据

1. **状态持久化在 `papers` 表**（`signal_state` / `signal_next_at` / `signal_last_at` /
   `signal_revived` / `prescreen_reason`），不建状态表。采样靠 `signal_next_at <= today` 触发，
   **不是每天全量重算** —— 否则新论文只有 1 个快照，永远没有增长曲线。
2. **两套时钟分离**：成熟度 = `published_at`（快路径 / 复活点）；观测窗口 = `first_seen`（90 天退出）。
3. **dormant 复活最多一次**：`signal_revived` 是硬闸，`--force` 也只采一次；
   复活条件**只**看 `citation_count ≥ min_citations`（age 只决定何时采）。
4. **预筛不决定入库**：`papers` 全量照收，预筛只写 `signal_state`（pending/ready/sample/rejected）。
   抽样用 `sha256(paper_id)` 取模 —— 可复现，单测不需要打桩随机数。
5. **选集**：`papers.selected`；`export` 默认只导 selected，`--all` 导最新 N 篇；
   首页改为"描述 vault 状态"（有笔记论文数），**不再写"本次导出 N 篇"** —— 否则换选集就 diff。
6. **观测值统一"已有值保留"**：`refs_count` 加入 `OBSERVED_KEYS`（与 `citations` 同）。
   L1-B 的 signals 会刷新 `refs_count`，若渲染直接取值 ⇒ 全库笔记每次导出都产生 diff。

### 踩到的坑

1. **`select_papers` 被 `list` 复用**：默认加 selected 过滤后，`list` 变成只看收藏。
   修法：`list` 显式 `all_papers=True`（"看库里有什么"不受选集限制）。
2. **首页内容依赖选集**：`00-首页.md` 里写"本次导出 N 篇" ⇒ 默认导出 2 篇与 `--ids` 导 42 篇
   会写出不同首页，幂等直接失效。修法：首页只描述 vault 状态（磁盘上已有笔记 ∪ 本次要写的）。
3. **`--check --all` 只查 `note_path` 非空的论文**：L1-0 时代的旧笔记没有回填 `note_path`，
   会被漏掉。修法：按论文算一遍目标路径，**文件存在就校验**。
4. **存量笔记格式升级**：L1-A 改了「关联文献」区，L0-C 的 20 篇旧笔记天然有 diff。
   一次性 `export --ids <42 个 id> --limit 100` 刷新后，`--check --all` 归零。
5. **`--check --all` 一度报 38 个 diff**：根因是 signals 刷新 `refs_count` 而笔记写的是旧值；
   把 `refs_count` 归入观测值后归零。**这不是幂等坏了，是渲染取值口径不一致**。

## L1-C（文献耦合 + TF-IDF 语义相似）

### 决策与依据

1. **`paper_references` 只落 db、只存外部 ID**（`ARXIV:` / `DOI:` / `S2:`），不存元数据、不进 JSONL。
   `enrich` 写库内命中的边时**同时**写引用列表 —— 这是文献耦合的原料（L1-A 时写边后就扔了）。
   ★ 没有 arxiv/doi 的引用退回 `S2:paperId`，保证耦合信号不丢。
2. **文献耦合必须倒排**：按 `ref_external_id` 分桶，计算量 = `Σ C(n,2)`。
   全量实测 **77,392 对**（全库两两是 236 万，30 倍差距随规模放大）。
3. **对称边只存一条**（`src_id < dst_id`），渲染时双向展开 —— 避免双倍行数与两套真相。
4. **相似度增量**：`papers.similar_at` 标记已比对；只算 `NULL` 的论文 vs 全量。
   TF-IDF 每次仍在全语料上拟合（2,174 篇约 6s），配对只做 pending —— 规模再大时把"拟合"也缓存即可。
5. **实体共现跳过**（卡允许）：抽实体需要词典/规则设计，收益低于耦合与相似，留到有正文时再做。

### 踩到的坑

1. **★ 对称边漏进「引用了」**：`load_link_refs` 只按 `src_id`/`dst_id` 过滤，没过滤 `link_type`，
   于是 `similarity` 边被当成引用渲染（真实笔记里出现「引用了 … — 相似 0.19」）。
   修法：出/入边查询加 `link_type == 'references'`，并加回归单测（引用区不得出现"相似"）。
2. **相似/耦合区前多一个空行**：`render_link_section` 自带结尾空行，前置 `""` 会变成双空行。去掉。
3. **测"sklearn 未安装"只把顶层包置 `None` 不够**：子模块已缓存，仍能 import 成功。
   必须把 `sklearn.*` 全部置 `None`。
4. **200 篇样本在阈值 0.1 下产出 0 条耦合边**：平均共现只有 1.52，Jaccard ≈ 1/70。
   阈值是硬约束，**没有为了"好看"调低**；全量 2,174 篇才有 294 条。

### 收尾复核（2026-10-24，打 `l1c` 后补）

按"导出物能不能直接喂给别的 AI"复核了一遍 L1-C，补掉三个洞：

1. **★ 无笔记的相似/耦合边不可解释**：`render_link_line` 原本只在有笔记时带 `evidence`，
   而绝大多数关联目标没有笔记 ⇒ 笔记里只剩「★ 标题（无笔记）— url」，
   读者无从判断为什么关联。现在相似度 / 共现数**双轨都渲染**；
   引用边的 `evidence` 是 `s2_references` 这类机器标记，按类型**不渲染**（引用是事实，无需解释）。
2. **`relate --dry-run` 把存量边全算成"新增"**：dry-run 分支无条件 `new += 1`，
   实测 294 条存量边被报成 294 新增，无法用来预估。改为两种模式都先查存在性。
3. **`similarity_strong_weight` 是死配置**：yaml 注释写"仅用于展示标注"，但没有任何代码读它。
   按设计方案 §3.6，它的消费方是 **L2「关联解读」选题**，本阶段不实现 —— 改注释，不假装配。

## L2-前置（模型名迁移 + 预算闸门）

### 决策与依据

1. **模型名迁移**：`deepseek-chat`/`deepseek-reasoner` 于 2026-07-24 弃用（成本预算 §1），
   新名 `deepseek-v4-flash`/`deepseek-v4-pro`。只改默认值，不做旧名兼容别名。
2. **`llm_usage` 记账闭环推迟到 L3**：阶段 0 无真实 LLM 调用点，现在补 `cost_cny`/`cache_hit`
   字段 + migration 是空造死配置（经验固化 E1）。闸门做成纯函数，L3 从 `llm_usage` 查
   「已花费」→ 组装 `BudgetState` → `check_budget`，接口零返工。
   ★ 待办已写入 `budget.py` docstring 作代码内锚点，L3 开工必读。
3. **预估按「未命中」保守计价**：调用前不知道缓存命中与否，按最贵的未命中单价算，
   实际命中与否在记账时回填（成本预算 §3.2）。
4. **`max_calls_per_run` 是天花板不是配额**：金额闸门（四层上限）先触发，次数闸门只兜底
   金额闸门失效（如估算 bug）时的无限调用。默认 100 ≈ 正常单日 20–25 次的 4–5 倍。

### 踩到的坑

1. **编辑 `cli.py` 的 `main()` 时误删 `try: app()`**：用 Edit 定位 main 时 old_string 带了
   `try: app()` 但 new_string 没带，导致 main 只剩 docstring + except。当场 `git diff` 发现并修复。
   教训：改函数体时 old/new_string 要一起看，不能只瞄目标行。
2. **ruff E501 超长 5 处**：f-string 里嵌中文 + 数字很容易超 100 列，提前拆行。

## L2-A（每日报告产物）

### 决策与依据

1. **报告模板放 `src/ai_scholar/templates/`**（与 `prompts/` 并列，包内）：加载稳定、随包分发。
   设计文档 §6.6 写的是 `templates/report/`，落包内更符合"prompt 放 src"的既有惯例。
2. **`DailyReport` 只含数据时间（`date`），不含生成时间**（红线 7）：当天重跑无 diff，
   幂等可测。成本说明（L3）是数据不是生成时间。
3. **深度分析 / 新定级留空占位**：L3 的能力，字段保留、恒空、渲染"暂无"，不假装配有数据。
4. **degraded 汇总用 `degraded_json` 的原始 key**（源名），不是 `run.source`：
   一次采集会按源写多行 `runs`，每行的 `degraded_json` 是整个 report 的降级表。
5. **report 输出到 `data/reports/`（仓库内）**：报告是 public 资产（阶段 2 commit 回 public），
   与 vault（必须仓库外）正好相反，不做仓库外校验。

### 踩到的坑

1. **Jinja `{% if %}` 块标签产生多余空行**：if/else 标签占一行，渲染后标签消失但换行残留。
   用 `{%-` / `-%}` 精确控制空白，实测空态/有数据两路都干净。
2. **mypy `no_implicit_reexport` 报 `attr-defined`**：`WatchlistConfig` 从 `config` re-export，
   strict 下不认。改从 `models` 直接 import（它本就在那里定义）。
3. **误加 `# type: ignore[arg-type]` 被 mypy 报 `unused-ignore`**：`col()` 用法本不需要 ignore。

## L2-B（daily.yml + commit 持久化）

### 决策与依据

1. **db 用 actions-cache 跨天续命，真源走 git**（§8.3 定案 C′）：
   `data/ai_scholar.db` 用固定 key `ai-scholar-db` 缓存；`first_seen.jsonl` / `signals` / 报告
   走 git commit。cache 失效只丢 db（可重采），不丢不可再生真源。
2. **daily 编排 = collect → enrich → signals → relate → report**：完整链路
   （采集 → 补齐引用 → 采样被引 → 关联 → 报告）。enrich 在 relate 之前（文献耦合原料）。
3. **commit 冲突用 `fetch + reset --soft FETCH_HEAD`**（坑 7），不用 `pull --rebase`；
   push 用 `HTTP/1.1`（本地 push 偶发 443 超时，坑 8）。
4. **cron 用 UTC 16:30 = 北京时间次日 00:30**；报告日期由 `today_local()`（Asia/Shanghai）决定。

### 踩到的坑

1. **本地模拟验证确认 hf_daily ConnectTimeout 是已知预期**：collect 退出码 0、只 warning、
   写 `runs.degraded_json`，report 正确把该降级读进「运行状态」—— 链路闭环验证通过。
2. **★ `reset --soft FETCH_HEAD` 会丢"checkout 之后远程新增 commit"的改动**（实跑踩中）：
   触发实跑后又 push 了文档，daily 的 `fetch + reset --soft + commit` 把该文档改动**回滚**了
   （`reset --soft` 只动 HEAD 指针、不动 index，commit 时 index 还是"旧 checkout + data 改动"）。
   修法：改用 `commit → fetch → rebase → push`（rebase 正确重放双方改动）。
   教训：坑 7 的 `reset --soft` 只适用于"远程无新 commit"的场景，不能当通用合并手段。
3. **★ 两个 actions/cache 步骤（Restore + 显式 Save）+ 固定 key 会互相覆盖**（第二次实跑踩中）：
   Save 步骤主步骤 hit 同一 key，用旧 db 覆盖 signals 更新 → signal_next_at 丢失 → 重采。
   修法：标准单一步骤 `key: run_id` + `restore-keys: 前缀`，post（job 末尾）自动保存，不写显式 Save。
4. **★ signals 幂等只查 db `signals` 表、不查 JSONL 真源**（第二次实跑踩中）：
   db 丢失/异常时 `signals` 表空 → 重新采样 → 重复污染 JSONL 真源（实跑产生 399 行重复）。
   修法：`_load_jsonl_seen` 加载 JSONL 已有的 `(paper_id, observed_at)`，采样前查重跳过。
   教训：**幂等的"真源"必须是不可再生的那份**（JSONL），不能是可丢弃的缓存（db）。

## L4（推演与演化，tag `l4`）

- **记分板是 public JSONL**：`data/predictions/scoreboard.jsonl` append-only；
