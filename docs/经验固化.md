> 维护方：**Agent**。高质量的经验教训、实践出的原则与技巧、总结出的指南，都落到这里。
> **分工**（避免双写漂移）：坑位清单（`执行手册.md` §4）= 具体某个坑；`开发日志.md` = 按时间的事实；

## 治理类（2026-10-24 与负责人商定）

### G1 全权 ≠ 无人驾驶
执行与文档全权交给 Agent，但 **push / tag / 不可逆操作必须逐次授权**。
**判据**：一个动作能否靠 `git` / 重跑找回 —— 找不回就报批。
**反例**：推 tag 上 public 不可逆；`export --all` 批量建笔记会让 vault 不可逆膨胀。

### G2 花钱路径先列后做
任何新增 LLM 调用点 / Actions / 第三方 API，开工前给出「单次 / 日 / 月 / 年」估算，
上线后**实测回填**。`off` 档必须恒 0。
**判据**：报告里出现"预计花费"却没有"实际花费"，视为未完成。

### G3 预算卡「调用前」，不卡「生成中」
**原则**：钱不够 = 少做或进队列，**不是降低单篇质量**。闸门在发起调用前预估并拦截，
绝不中途截断生成。
**反例**：为了不超 max_tokens 而让模型回显摘要、砍掉六段之一 —— 那是质量事故，不是省钱。

### G4 交接文档要能「盲测」
阶段交接文档质量门槛：**新 Agent 只读 CODEBUDDY.md + handoff 能独立跑通并说出风险**。
写法：写完后自己不看对话、照文档走一遍，走不通就是不合格。

### G5 本地开发不得覆盖公共真源（2026-10-25 实锤）

**规则**：`data/reports` / `data/signals` / `data/predictions` / `data/first_seen.jsonl`
由 **daily bot** 负责提交；本地跑管道后**不要把它们一并 commit**。

**Why**：L4 提交时顺手 `git add data/`，把本地 `2026-10-25` 报告覆盖到 bot 产物上：
bot 版含 `runs=1` + `degraded={hf_daily: HTTP 400}`，本地版变成 `runs=0` + `degraded={}`。
结果**降级证据在 public 产物里消失**，而日志里明明有 HF 400。这不是代码 bug，
是数据来源被本地缓存覆盖 —— 比代码 bug 更难发现。

**How to apply**：
- 提交前 `git status` 看清 `data/` 改动来源：本地 `report` 生成的报告不要提交；
- 只有需要修正历史产物时才手动改 `data/`，并在 commit message 说明来源；
- `site` / `report` 展示降级信息依赖 `runs.degraded_json`，真源被覆盖 = 面板"看起来正常"。

## 成本类

### C1 成本失控是「叠乘」，不是「单价」
```
500 篇/天 × 50k 全文 × 1 元/M = 25 元/天 ≈ 9,000 元/年
```
单看单价不贵，一次「图省事对全量做深度分析」就是 60 倍。
**原则**：闸门必须同时卡「篇数 × 上下文长度 × 调用次数」，缺一不可。

### C2 单价模型要三档，单一数字必错
计费是「输入命中 / 输入未命中 / 输出」三档，输出单价常是输入的 2 倍。
**反例**：`config/default.yaml` 原 `price_fast_cny_per_1m: 1.0` 单一数字，无论怎么填都系统性低估。

## 工程类

### E1 死配置要么接消费者，要么写明「消费方在哪个阶段」
**反例**：`similarity_strong_weight`（0.30）无人读 —— 留下"看起来已实现"的假象。
`budget` 块同理。**判据**：每个配置项在源码里 grep 得到消费方，否则视为未完成。

### E2 测试绿 ≠ 功能完整
206 测试全绿、`export --check` 0 变更，仍漏了三个洞（无笔记边不显示相似度 /
`--dry-run` 把存量报成新增 / 死配置）。
**原则**：推送前按任务卡 DoD 与「可解释性 / 幂等 / 降级」三条逐一对，不看 pytest 数。

### E3 断言打在「真实结构」，不打在「看起来对」的东西上
**反例**：`assert "★" in output` 命中脚注说明文字 → 恒真（本项目已三次踩中，红线 18）。
**判据**：写断言前先问「这条断言在什么情况下恒真 / 恒假」。

---

### E4 统计分母必须显式排除「无法判断」

命中率的分母只能是 **hit + miss**；`insufficient`（数据不足）与「观点」都要单独列。
**反例**：把"样本不足"算成 miss，会让早期命中率虚低；算成 hit 则会美化评测。
**判据**：任何比率输出都要能回答「分母是什么、排除了什么」。
**落地**：`pipeline/stats.py` 的 `insufficient` 不进分母；`opinions.jsonl` 永不进统计。

### E5 失败信息必须能自证，不能只报状态码

**规则**：对外部源的失败，错误文案要带**截断的响应体**与请求关键参数
（URL / 日期）。`HF HTTP 400` 这种只有状态码的消息，等于让下一个人从零猜。

**Why**（2026-10-25 实锤）：排查 HF 400 时 daily 日志只有 `HF HTTP 400`，
第一反应是「网络 / 镜像 / IP 被限」。实测镜像与官方同行为，才发现
官方 API 对「今天」直接 400：`"date" must be less than or equal to "<今天>"` ——
是**榜单发布延迟**，正确修法是把窗口改成从昨天开始，而不是换源。

**How to apply**：
- 采集器抛错时附 `response.text[:300]`（去换行），并带日期 / URL；
- 判据：只看错误信息，能否直接分清「是源的问题还是我们的参数问题」；
- 连带教训：外部源的能力与边界**先实测再接线**（D1），尤其"边界值 / 回退源"。

### E6 max_tokens 要按「推理 + 答案」设，不能按答案长度设

**规则**：给带推理的模型设 `max_tokens` 时，预算 = **推理 token + 正式答案 token**，
只按答案长度估必翻车。

**Why**（2026-10-25 端到端实测）：`max_tokens_fast=4000` 下，定级输出停在定级表表头，
`tokens_out=3999` 正好顶格 —— token 被推理吃光，答案被截断，`Tier` 解析失败。
抬到 8000 后同一次请求即成功。`max_tokens_strong=8000` 也已顶格（两次深度分析
`tokens_out≈7998`），属于侥幸没截断。

**How to apply**：
- 改 `max_tokens` 前先看 `llm_usage.tokens_out` 的**实际分布**，不要拍脑袋；
- 出现「结构化输出缺尾 / 解析失败」先查 `tokens_out` 是否顶格，再查 prompt；
- 抬上限不强制多产出（输出按实际计费），但**要复跑确认成本没异常**；
- 截断的自愈机制已设计好：解析失败 ⇒ 不写指纹 ⇒ 下次重试，不要为了"这次成功"降低质量要求。

### E7 验收必须查「跨阶段接缝」，不能只验收「能力」

**规则**：阶段 DoD 除了验收本阶段能力，必须显式回答一句——
**「本阶段的产出，下一个阶段/最终用户凭什么拿到它？」**答不上来就是接线缺失。

**Why**（2026-10-25 L7 前置审计实锤）：
- `deep_analysis.py` 的双通道选篇代码**早就写好了**，报告的「深度分析」板块
  （`daily.md.j2` + `report.py`）**也早就写好了**，但：
  - `analyze` **从未接入任何自动管道**（唯一调用者是 CLI）
  - 深度分析完成 **不置 `selected`**（全仓库只有 `mark` 写它）
  ⇒「每日一篇 → 深度分析 → 沉淀进 vault」整条链**两头断在接线处**，
  而每个阶段都是绿灯——因为 L3b-2 的 DoD 是「对 1 篇真实论文跑出完整分析」，
  按这个标准，能跑就算过，接不接管道不在验收范围。

**根因**：设计文档 §5.6 写明「置位途径**随对应阶段接入**」，但**没有任何阶段的
任务卡把这三条途径列为 DoD** ⇒ 无主事项，一路合法放行。

**How to apply**：
- 写阶段 DoD 时，对每个"以后要用"的字段/产物，指定**唯一责任阶段**并写进该阶段 DoD；
- 收尾自查（E2）增加一项：`grep` 该产物的**写入点**，确认不是"只有我一个人在写"；
- 看到"随对应阶段接入"这类措辞，立刻建任务卡，不允许停留在散文里。

## 数据类

### D1 能用实测替代推断的，不要推
引用命中率推了三轮都错，实测一次即推翻（0.0095% ≈ 零）。
**原则**：体积 / 关联 / 命中率这类量级判断，先实测，不靠推断。拿不到真值就 `skip`，不伪造。

★ **反例（2026-10-25）**：曾据「ar5iv 是 arXiv HTML 镜像」推断它可作正文回退源；
实测发现它对**有 HTML 和没有 HTML 的论文都只返回约 5k 字符的 arXiv 摘要页**（导航 + 主题分类），
不是正文。若照推断实现，prompt 会误以为有全文，比返回 `None` 更糟。
⇒ **外部源的能力先实测再接线**，尤其是「回退源」——错的回退会伪装成真数据。

## 输出规范类（2026-10-24 与负责人商定）

### O1 两张进度表（每个大小阶段都遵循）

每次阶段输出固定两张表，让负责人一眼看清「全局在哪」与「当前阶段到哪」：

**表 1 · 项目整体进度**（所有里程碑，当前 + 前序 + 后序，标注状态）：

| 阶段 | 内容 | 状态 |
|---|---|---|
| L0-A/B/C | 骨架 / DB / 导出器 | ✅ 完成 |
| L1-0 | vault 迁出 | ✅ 完成 |
| L1-A/B/C | S2 / signals / 耦合+相似 | ✅ 完成 |
| **L2** | Actions 自动化 + 每日报告 | ✅ 完成 |
| **L2-C** | Daily Note（`40-日志/`） | ✅ 完成 |
| L3a / L3b | LLM 增强 / 定级+深度分析 | ✅ 完成 |
| L4 / L5 | 推演 / 呈现形态 | ⬜ 未开始 |

**表 2 · 当前大阶段分级进展**（与项目文档/任务卡对齐）：

| 子阶段 | 内容 | 状态 | 验证证据 |
|---|---|---|---|
| L2-前置 | 模型名迁移 + 预算闸门 | ✅ 完成 | 测试全过、真实运行成功 |
| L2-A | 每日报告产物 | ✅ 完成 | 测试全过、实跑产出正常 |
| L2-B | daily.yml + commit 机制 | ✅ 完成 | 实跑全链路通过 |
| L2-C | Daily Note（`40-日志/`） | ✅ 完成 | 测试全过、用户区不被覆盖、连续两次导出无 diff |

★「验证证据」列用**通俗结果**表述（「测试全过」「真实运行成功」），
不用代码覆盖率等技术数字 —— 让负责人一眼看懂，不暴露实现细节。

**待决策的固定子格式**：`决策项 → 理由 → 影响 → 利弊 → 推荐`，
每条决策都按这个顺序写，负责人不用在长文里自己提炼。

**Why**：项目跨多阶段、每阶段又分子阶段，纯文字叙述负责人要自己拼进度。
**How to apply**：阶段名、子阶段划分、状态标记（✅/🔄/⬜）与 `执行手册.md` §5、`设计方案.md` §8 对齐，不另造口径。

### O2 阶段收尾 = 下一阶段 handoff 就位（clear/init 前置）

**规则**：每个大阶段宣布完成前，必须**新建** `docs/handoff/L{下一阶段}-开工.md`；
当前阶段文件标「已归档」并指向新文件。下一阶段 Agent 只靠它恢复上下文。

**Why**：每个大阶段结束都会 **clear + init**，上下文归零；handoff 缺失 = 下阶段在无上下文下开工。
2026-10-25 实际发生过：把 L4 内容写进 `L3-开工.md`，文件名仍锚定 L3，靠负责人提醒才发现。

**How to apply**：
- 收尾清单显式包含「新建下一阶段 handoff」+「当前阶段归档」；
- 跑 `uv run pytest tests/test_docs_consistency.py -q`（机械校验下一阶段 handoff 存在且未归档）；
- ★ **不要只改现有 handoff 的内容** —— 文件按阶段命名，**内容更新 ≠ 交接完成**。

### E8 「判废」要看顶格，不能只看"有没有内容"（2026-10-26 Actions 实锤）

**规则**：结构化 LLM 输出的验收 = 骨架 + 长度 + **`tokens_out` 是否顶格**。
顶格 = 推理把额度吃光，答案即使"看起来有结构"也是残稿；空内容 + 顶格 = 纯烧钱。

**Why**：strong 档带 100k 正文时，`max_tokens=8000` 被推理吃满（`tokens_out=8000`、
`content` 0 字符），5 次调用只 1 次成功，**80% 花费是废调用**（¥0.2361）。
更隐蔽的是：当时的判据是"`paper_id` 是否回显"——真实模型经常不回显，
于是把"截断"误诊成"不听话"，修错方向。

**How to apply**：
- `validate_output(content, tokens_out=..., max_tokens=...)`：空/短/缺骨架/顶格，四种都判废；
- 判废理由必须带 **tokens_out 与字符数**（否则下一个人只能猜，E5）；
- 抬 `max_tokens` 前先看 `llm_usage.tokens_out` 的分布，别按"答案长度"估（E6）。

### E9 预算保护要「口径对齐产出 + 连续失败刹车」（2026-10-26 负责人定性为严重缺陷）

**规则**：① 任何"配额/预算"的口径必须与**产出**对齐（篇、条），不能按"尝试次数"；
② 同一批里连续失败 N 次（默认 2）必须**中止本轮**，不许把剩余候选一路付费烧完。

**Why**：首次 Actions 里 4 次废调用按"调用"计直接吃掉整周 5 篇配额 ⇒
之后一周无法分析（`blocked=5`），钱花了、额度也没了 —— 双重浪费。

**How to apply**：
- 写配额逻辑前先问："这个数代表**产出**还是**尝试**？"；
- 失败是信息：连续失败通常意味着系统性原因（额度不足 / 模型不兼容 / prompt 崩了），
  继续重试只会放大损失；
- 刹车后必须把"已花成本 + 中止原因"写进 `degraded`，让人知道为什么停。
